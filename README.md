# Тестовое задание / AbeloHost.

Небольшой блог на чистом PHP 8.1+ с использованием Smarty и MySQL. Проект запускается в Docker и не использует PHP-фреймворки.

## Использование ИИ

В процессе разработки использовался ИИ как вспомогательный инструмент.

ИИ использовался для:

* подготовки данного README;
* обсуждения архитектуры проекта и разделения ответственности между контроллерами, репозиториями и сервисами;
* анализа и рефакторинга существующего кода;
* поиска потенциальных проблем и проверки отдельных решений;
* помощи в написании и структурировании CSS, SCSS;
* помощи при создании `MigrationRunner`;
* помощи при создании `SeederRunner`;
* проверки SQL-запросов и структуры взаимодействия с базой данных;
* обсуждения возможных вариантов реализации отдельных частей проекта.


## Стек

* PHP 8.3
* MySQL 8.0
* Smarty 5
* PDO
* Docker / Docker Compose
* Nginx
* SCSS
* Composer
* npm

## Возможности

* Главная страница с категориями и тремя последними статьями в каждой категории.
* Страница категории со списком статей.
* Сортировка статей по дате публикации и количеству просмотров.
* Пагинация.
* Страница отдельной статьи.
* Счётчик просмотров.
* Три похожие статьи на странице статьи.
* Страница 404.
* Миграции базы данных.
* Seeders для заполнения тестовыми данными.
* Адаптивная вёрстка.

```text
app/
└── Blog/
```

Основная логика приложения разделена на контроллеры, репозитории, модели и сервисы.

Контроллеры отвечают за обработку запросов и подготовку данных для представлений. Репозитории работают с базой данных через PDO. Модели используются для представления сущностей приложения. Сервисы содержат инфраструктурную логику, например запуск миграций и seeders.

## Требования

Для запуска проекта достаточно:

* Docker
* Docker Compose
* Git

PHP, Composer, MySQL и Node.js устанавливать локально не требуется.

## Развёртывание

Клонировать репозиторий:
```bash
git clone https://github.com/Skeeze-Ord/AbeloHost
cd AbeloHost
```

Запустить Docker-контейнеры:
```bash
docker compose up -d --build
```

Установить PHP-зависимости:
```bash
docker compose exec php composer install
```

Выполнить миграции:
```bash
docker compose exec php php database/migrate.php
```

Заполнить базу тестовыми данными:
```bash
docker compose exec php php database/seed.php
```

После этого проект доступен по адресу:
```text
http://localhost:8080
```

## Сборка стилей

Исходные SCSS-файлы находятся в:
```text
resources/scss/
```

Скомпилированный CSS:
```text
public/assets/css/main.css
```

Установить frontend-зависимости:
```bash
npm install
```

Собрать CSS:
```bash
npm run sass
```

Для автоматической пересборки во время разработки:
```bash
npm run sass:watch
```

## Основные маршруты

| URL                           | Описание                  |
| ----------------------------- | ------------------------- |
| `/`                           | Главная страница          |
| `/categories/{id}`            | Страница категории        |
| `/categories/{id}?sort=date`  | Сортировка по дате        |
| `/categories/{id}?sort=views` | Сортировка по просмотрам  |
| `/categories/{id}?page=2`     | Вторая страница категории |
| `/posts/{id}`                 | Страница статьи           |

## База данных

Проект использует три основные таблицы:

* `blog_posts` — статьи;
* `blog_categories` — категории;
* `blog_posts_categories` — связь многие-ко-многим между статьями и категориями.

Также используются служебные таблицы:

* `blog_migrations` — выполненные миграции;
* `blog_seeders` — выполненные seeders.

Связь статьи с несколькими категориями реализована через таблицу `blog_posts_categories`.

## Миграции и seeders

Миграции находятся в:
```text
database/Blog/migrations/
```

Seeders находятся в:
```text
database/Blog/seeders/
```

Для отслеживания уже выполненных миграций и seeders используются отдельные таблицы.

Запуск:
```bash
docker compose exec php php database/migrate.php
docker compose exec php php database/seed.php
```

## Архитектурные решения

Проект намеренно реализован без фреймворка, поэтому некоторые инфраструктурные компоненты, которые обычно предоставляет Laravel или другой PHP-фреймворк, реализованы самостоятельно.

В частности:

* простой роутинг;
* `ControllerFactory`;
* `MigrationRunner`;
* `SeederRunner`;
* обработка 404 через собственное исключение `NotFoundException`.

Работа с базой данных выполняется через PDO и подготовленные выражения.

Для сортировки используется whitelist допустимых значений, чтобы значение параметра запроса не могло напрямую попасть в SQL `ORDER BY`.

## Известные особенности

На главной странице категории загружаются отдельным запросом последние три статьи для каждой категории. Для небольшого количества категорий такая реализация оставлена намеренно простой и читаемой.

При значительном увеличении количества категорий этот участок можно оптимизировать, например, получая последние N статей всех категорий одним SQL-запросом с использованием оконной функции `ROW_NUMBER()`.
